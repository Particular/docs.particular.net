ServiceControl version 7 changes event logging and disables integration event publishing by default. An in-place upgrade retains the existing RavenDB storage; it does not migrate data to SQL Server or PostgreSQL.

## Prerequisites

Review the [upgrade tips](/servicecontrol/upgrades/) and [back up the RavenDB database](/servicecontrol/storage/ravendb/backup-sc-database.md) before upgrading.

## Event log changes

ServiceControl no longer creates event log entries for individual message failures. This reduces write and retention overhead in the event log.

View failed messages on the failed messages screen in ServicePulse instead. If an integration reads the event log to detect message failures, update it to [subscribe to `MessageFailed` integration events](/servicecontrol/contracts.md#messagefailed-events) and enable integration event publishing as described below.

## Integration events disabled by default

ServiceControl version 7 disables [integration event publishing](/servicecontrol/contracts.md) by default. Previously, publishing was enabled by default.

> [!WARNING]
> If subscribers rely on integration events, enable publishing before upgrading. Otherwise they stop receiving events after the upgrade, without any error.

If subscribers use these events for custom notifications or integrations, set [`ServiceControl/EnableExternalIntegrationsPublishing`](/servicecontrol/servicecontrol-instances/configuration.md#host-settings-servicecontrolenableexternalintegrationspublishing) to `true` to continue publishing after upgrading. For container deployments, set the `SERVICECONTROL_ENABLEEXTERNALINTEGRATIONSPUBLISHING` environment variable to `true`.

An existing explicit [`ServiceControl/DisableExternalIntegrationsPublishing`](/servicecontrol/servicecontrol-instances/configuration.md#host-settings-servicecontroldisableexternalintegrationspublishing) value of `false` continues to enable publishing, but replace it with the new setting. Do not configure both settings; ServiceControl does not start when both are present. No configuration change is required if the feature is not used.

## Error instance audit retention setting removed

Error instances no longer read the `ServiceControl/AuditRetentionPeriod` setting, which had no effect on them, and upgrading an instance removes it from the configuration file. The objects returned by `Get-ServiceControlInstances` no longer have an `AuditRetentionPeriod` property. Audit retention is configured on each Audit instance with [`ServiceControl.Audit/AuditRetentionPeriod`](/servicecontrol/audit-instances/configuration.md#data-retention-servicecontrol-auditauditretentionperiod).

## Maintenance mode restricted to embedded RavenDB

Error and Audit instances using an external RavenDB server no longer start in maintenance mode. Maintenance mode remains available for embedded RavenDB, where ServiceControl manages the database process.

If an instance uses external RavenDB, set `ServiceControl/MaintenanceMode` or `ServiceControl.Audit/MaintenanceMode` to `false` and remove maintenance-mode arguments from startup commands. To perform database maintenance, stop the ServiceControl instance and access the external database directly, leaving the database server running. For container deployments, stop the ServiceControl container while leaving the database container running. See [accessing the ServiceControl database](/servicecontrol/storage/ravendb/accessing-database.md).

## Support for version 6

Version 6 is supported for one year after version 7 is released as defined by the [ServiceControl support policy](/servicecontrol/upgrades/support-policy.md). The ServiceControl support end date is available at [ServiceControl supported versions](/servicecontrol/upgrades/supported-versions.md).
