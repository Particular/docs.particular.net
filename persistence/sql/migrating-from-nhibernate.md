## Schema

The database schemas for [NHibernate](/persistence/nhibernate) and [SQL](/persistence/sql) persisters are not compatible.

Review the schema generated by each persister before migrating data. For SQL Server, see the scripting pages:

- [NHibernate persistence scripts](/persistence/nhibernate/#generating-scripts-for-deployment)
- [SQL persistence SQL Server scripts](/persistence/sql/sqlserver-scripts.md)

### Sagas

- NHibernate: maps saga data to relational table columns.
- SQL Persistence: serializes saga data and metadata as JSON, with saga IDs and correlation values stored separately.

### Subscriptions

- NHibernate: stores subscriptions in a `Subscription` table by default.
- SQL Persistence: uses a separate `<table_prefix>SubscriptionData` table for each logical endpoint. By default, the table prefix is the endpoint name with periods replaced by underscores; it can be configured using the [table prefix setting](/persistence/sql/install.md#table-prefix).

### Timeouts

- NHibernate: stores timeouts in a `TimeoutEntity` table with an `Endpoint` column.
- SQL Persistence: uses a separate `<table_prefix>TimeoutData` table for each endpoint.

### Outbox

- NHibernate: stores outbox records in an `OutboxRecord` table shared by endpoints. In later versions, the endpoint name is prepended to the message ID.
- SQL Persistence: uses a separate `<table_prefix>OutboxData` table for each logical endpoint.

## Outbox retention

Longer outbox retention and high message throughput can increase the amount of data to migrate and migration time. Keeping the retention period as low as possible is recommended.

- [NHibernate Deduplication record lifespan](/persistence/nhibernate/outbox.md#deduplication-record-lifespan)
- [SQL Persistence Deduplication record lifespan](/persistence/sql/outbox.md#deduplication-record-lifespan)

## Data migration

### Conversion

Subscription, timeout, and outbox data can be migrated with custom scripts that map the source schema to the target schema. Use the generated target schema and account for configured table names; this page does not provide ready-made conversion scripts.

Saga state migration is more complex. NHibernate maps saga properties to relational columns, while SQL Persistence stores saga data and metadata as JSON and stores correlation values separately. Create and validate mappings for each saga type, preserving saga IDs and correlation values.

### Migration downtime

Migration downtime depends on:

- The deployment complexity
- Whether custom saga migration mappings are needed
- The data set size
- The complexity of saga state
- Whether outbox, timeout, and subscription data must be migrated
